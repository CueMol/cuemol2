# パレットのテーマを GUI から選ぶ

分子の既定の色分けは、style の `<palette id="default_paint" value="..."/>` が指すテーマの
色で塗る (実装済みの仕様は
[`../architecture/default-paint-palette.md`](../architecture/default-paint-palette.md))。
テーマは今は style を手で書き換えて切り替える。これを GUI から選べるようにする。

## 方針 (案)

- テーマの一覧は全体の色名 (`<テーマ名>_<番号>`) から作る。テーマの表示名や出典を出すなら、
  テーマごとの説明を style に足す。
- 選んだテーマは、全体の既定 (ユーザーの style set に `default_paint` を書く) と、
  その scene だけ (scene の style set に書く) の 2 通りを考える。
- テーマはこれから読み込む分子の塗り方だけを決める (塗り済みの分子は変えない)。
  色数がテーマごとに違うため、既存の分子をまとめて別のテーマに塗り替えることはしない。

## 未決の点

- GUI の置き場所 (設定画面、scene tree の Styles、coloring パネルのどれか)。
- 修飾子の値 (核酸の色相のずれ、coil の淡さ) をテーマごとに持たせるか。今は共通で、淡い
  テーマでは coil や核酸との差が小さくなる。
- 濃淡の段の作り方。今の修飾子は HSB の足し算なので、同じ値でも主色によって効き方がばらつく
  (彩度の低い色はすぐ灰白色になる、明るい色はそれ以上明るくならない)。任意のテーマで段を
  揃えたいなら、白 / 黒との混合割合で指定する修飾子 (Illustrator / Affinity の tint に相当) を
  C++ の NamedColor に足すことを検討する。ただし古い CueMol はその修飾子を読めないので、
  scene に定義を埋め込んでも互換性が失われる。足し算のままテーマごとに値を調整する案と比べて決める。
- 色を個別に選ぶスウォッチを作るなら、そのマスと既定の各構造の修飾子を揃え、既定色が
  どれかのマスに当たるようにする。3D では明るさの差だけだと陰影に紛れて別の色と認識されにくい
  ので、2D のツール (Illustrator / Affinity / PowerPoint の濃淡) と違い、色相を少しずらした
  変種 (既定の核酸は +15 度) もマスに含める。
