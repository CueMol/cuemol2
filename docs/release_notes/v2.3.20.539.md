CueMol 2.3.20 (build 539)

This release is mostly about size. **MD trajectories of millions of atoms now
open at once and play back at the display rate**: frames are read only when
they are shown, the frames kept in memory are capped, the next frames are
decoded in the background while you play, and water you do not want to see can
be left out of the trajectory altogether. The molecule underneath takes less
memory per atom, very large GRO files load in well under half the time, and a
molecule whose coordinates change every frame no longer costs the CPU most of
the frame.

The **PyM Console** grows from a command line into something that runs PyMOL
scripts: `@script.pml`, `save`, `label`, `align` / `super`, `spectrum`,
`orient`, `get_view` / `set_view`, object names inside selections, and PyMOL's
own `show` / `hide` and argument conventions. The **AI agent** gains Google
Gemini, a model picker, and a tool that lets the model look at the current view.

There is one new renderer, **`tracestick`** -- `trace` drawn as balls and
sticks -- and three fixes to what you see: the cartoon coil no longer pokes out
of a cylinder helix, high anti-aliasing no longer drops frames while the view
moves, and SSM superposition works on structures with alternate residue types.

CueMol2 (the UXP app) picks up the shared core work: the trajectory and memory
changes, the cartoon and anti-aliasing fixes, the SSM fix and the new renderer
class.

## MD trajectories

**A trajectory the reader could open is no longer reported as corrupt.**
Dropping an `.xtc`, `.dcd` or `.trr` file on the window said the file could not
be read, might be corrupt, or had the wrong extension -- none of which was true.
A trajectory file holds only frames and cannot be opened on its own. The message
now says so and points to *File > Open MD Trajectory...*, and, when the MD Tools
plugin is off, first to **Settings > Plugins** to turn it on. *File > Open* no
longer lists the trajectory formats at all, since they always led nowhere there.

**Frames are read when they are shown.** Opening a trajectory used to decode
every frame before anything appeared -- 746 MB for one user's 400k-atom membrane
system, with the app frozen meanwhile. DCD, XTC and TRR now index the file on
open and decode a frame the first time it is shown. A file cut short while it was
being written is still detected when it is opened. AMBER NetCDF and trajectories
restored from a `.qsc` file are still read in full.

**Memory stays bounded however long the trajectory is.** A lazily read
trajectory keeps at most 2 GiB of decoded frames per block and releases the
least recently shown ones past that. At 3.9 million atoms a frame is 47 MB, so a
2,530-frame trajectory would otherwise have grown towards 119 GB.

**Playback decodes ahead.** While an XTC trajectory plays, the next four frames
in the direction of playback are decoded on background threads, so a frame is
usually ready before it is needed. On a 3.9M-atom system with the water left out
this took first-pass playback from 30 to 60 fps. XTC decoding itself is also about
a third faster. DCD and TRR do not decode ahead yet.

**Water can be left out of the trajectory.** `Trajectory.applyLoadSel(sel)`
keeps only the selected atoms, so frames are stored, copied and drawn for those
atoms alone. It is saved in the `.qsc` file. On the same 3.9M-atom system,
dropping the water instead of hiding it took playback from about 30 to 52 fps and
halved the memory. For now it is available from scripts; there is no GUI for it
yet.

**Large GRO files load faster and log less.** A 3.9M-atom `.gro` file loads in
4.8 s instead of 12.5 s, with an identical result. A residue-number reset in a
`.gro` file is where the next molecule starts, not a problem, so the log no
longer prints one warning per reset: the first ten are shown and the rest are
summed up in one line (532 lines down to 13 for the file above).

## Performance and memory

- **Molecules take less memory per atom.** Atom and residue names are interned,
  positions, occupancies and B-factors are stored in single precision (they were
  read and written that way already), and bookkeeping that almost every atom left
  empty is now allocated only when used. Script and GUI interfaces are unchanged.
- **A molecule whose coordinates change every frame is cheap to draw.** For
  trajectories and morphs, the per-frame CPU time on a 237k-atom structure went
  from 26 ms to 1.6 ms (25 to 60 fps), and on a 2.4M-atom structure from 36 to
  54 fps. Coordinate uploads to the GPU no longer allocate a new buffer each
  frame and no longer write into a texture the GPU is still reading.
- **Static viewing costs about the same at any size.** An empty selection
  renderer used to rebuild itself every frame; with nothing selected -- the usual
  state -- every scene paid for it.

## Rendering

- **New `tracestick` renderer**: the main-chain pivot atoms (CA for proteins, P
  for nucleic acids) as spheres, joined by cylinders between linked residues.
  It breaks where `trace` breaks. Four styles ship with it: `DefaultTraceStick`,
  `ThickTraceStick`, `BallTraceStick` and `ThickBallTraceStick`. CueMol3 has an
  inspector section for it.
- **The cartoon coil stays inside a cylinder helix.** At a helix-coil junction
  the coil passed through the terminal residue's CA, so it stuck out of the
  cylinder when that CA lay outside it (for example 2BTE chain A 510). Junctions
  whose CA is already inside are drawn as before; ribbon helices are unchanged.
- **High and Ultra anti-aliasing no longer drop frames while the view moves.**
  Temporal jitter now accumulates only once the view has been still for 100 ms;
  a moving frame is drawn at the plain anti-aliasing cost. In CueMol3 the scene
  was also being updated twice per frame, which is fixed.

## Superposition

**SSM superposition works on structures with microheterogeneity.** A structure
that models two residue types at one position through alternate locations, such
as 1EJG, failed with "Coordinate conversion for MMDB is failed!!". Only atoms
with no alternate location or location `A` are now given to SSM. This applies to
the Superpose dialog in both apps and to the PyM Console's `align` / `super`.

## PyM Console (CueMol3, off by default)

Turn it on in **Settings > Plugins**.

- **Scripts and logs**: `@file.pml` and `run file.pml` run a script -- nested ones
  included -- as one undo step. `log_open` / `log_close` / `log` record what you
  type, so a log replays with `@`. A **Stop** button stops before the next command
  and cancels a download in progress.
- **New commands**: `save` (`.pdb` / `.sdf` / `.mol` with a selection, `.qsc`,
  `.png`, `.pqr`, `.pov`, `.stl`), `set_color`, `spectrum`, `align` / `super` /
  `pair_fit` with the RMSD, `get_view` / `set_view` in PyMOL's 18-number form,
  `mplay` / `mstop` / `rewind`, `frame` / `count_states`, `label` with PyMOL
  expressions, and `orient`.
- **`load` and `fetch` do more**: `load` opens `.qsc` (into a new tab unless the
  scene is new and empty), `.pse`, `.pml` and `http(s)://` URLs; `fetch` takes
  `type=2fofc|fofc` for density maps, `type=pdbN` for a biological assembly, and
  `1abcA` / `1abc_A` for one chain.
- **Behaves more like PyMOL**: object names work inside selections
  (`1abc and chain A`); `show` / `hide` take no argument, `everything`,
  abbreviated and space-separated representation names, and `show_as`; hiding
  something and showing part of it again no longer brings back the rest; PyMOL
  keyword and positional arguments such as `quiet=1` and `async=0` are accepted;
  `distance` with a `cutoff` or `mode` lists contacts; and PyMOL settings such as
  `stick_radius`, `transparency`, `line_width`, `solvent_radius`, `label_size`
  and `label_color` are mapped where CueMol has the same quantity. A setting made
  before `show` applies to what is shown later, as scripts expect.
- `color`, `zoom` and `center` no longer change the molecule's current selection.
- Cmd/Ctrl+A in the transcript selects the transcript text.

## AI agent (CueMol3, off by default)

- **Google Gemini** is a third provider, written `google:<model>`, with a
  "Google AI API key" setting (or `GEMINI_API_KEY`).
- **A model picker** at the top of the panel lists only models the stored API
  keys can run, and updates when a key is added or removed.
- **`capture_view`**: the model can render the current view and look at it,
  so it can check its own work. The picture is shown as a thumbnail on the tool
  row. Only the latest picture is kept in the conversation.

## Other fixes in CueMol3

- *Select All* in the macOS text context menu selected the whole window instead
  of the text field it was used in.
- Name labels take a format: the name label renderer's new `format` property
  (`{resn} {resi}`, `{bfac:.1f}` and so on) replaces the built-in text when set.
  A label's text and format are
  saved in the `.qsc` file, and a label that was read but not yet drawn is no
  longer lost on save.

## Known incompatibilities and limitations

- **Coordinates of an animated molecule cannot be edited atom by atom.** In a
  trajectory or a morph the frames define the coordinates; such an edit never
  survived the next frame change, and it is now refused up front. Moving the
  whole molecule through its transform still works for morphs.
- **A trajectory ignores a molecule transform (`xformMat`)**, with a warning,
  because superposing a trajectory only makes sense frame by frame. Old `.qsc`
  files still load. The CueMol2 Superpose dialog no longer offers a trajectory as
  the moving molecule, matching CueMol3.
- **Positions, occupancies and B-factors are held in single precision.** Values
  read back through scripts are the float-rounded ones.
- **Frames of a trajectory restored from `.qsc` are read in full**, as before;
  lazy reading applies to trajectories opened from *File > Open MD Trajectory...*.
  AMBER NetCDF is always read in full. Background decoding covers XTC only.
- **`applyLoadSel` has no GUI yet**, and round-tripping a load selection through
  `.qsc` has not been tried in the app.
- The PyM Console still lacks, among others, the MD trajectory commands
  (`load_traj`, `intra_fit`, `smooth`, ...), picking-dependent commands and
  `volume` / `isodot`; `.cif` and `.pse` cannot be saved.
