CueMol 2.3.8 (build 494)

This release is mostly about **CueMol3**, the new desktop app. Ray-traced and
non-photorealistic rendering, movie output, MD trajectory playback and a large
batch of UXP feature ports all landed since 2.3.7. CueMol2 (the UXP app) is
still built and shipped here, and receives several core fixes it shares with
CueMol3.

Note that CueMol3 is still a work in progress and does not yet cover everything
CueMol2 does.

---

## Rendering

**A ray tracer is now included in the builds.** Umbreon (an Embree-based ray
tracer) ships in every downloadable artifact — previously it was compiled out,
so it was unusable in a release build. Pick it in the Rendering window's backend
selector, next to POV-Ray. It renders in-process, with no external program to
install.

**Umbreon (NPR)** is a second, new backend that draws the scene as an ink
illustration, shading with hatch marks on paper. The Hatching group controls
style, mark density and width, a colouring pattern (pen drawing, coloured
pencil, comic, print-like, or the style default), and optional ink and paper
colours; the paper colour is applied to the background and fog so the whole
sheet reads as paper. Lighting here is Raytrace only or Ambient Occlusion — the
hatch-ink mode discards colour, so GI does not apply.

**Movie rendering** is back. The Rendering window has Still / Movie modes: it
renders frames in sequence and encodes them with ffmpeg, showing overall
progress and a live preview, and afterwards lets you step through frames, open
or reveal the result, re-encode without re-rendering, or clean up intermediate
frames. Resolution presets run from QVGA to HD1080. Both backends can render
movies. Output defaults to a managed temporary folder, so nothing has to be
configured before the first render; switch to a folder of your own with
Location, and lift a finished movie out of the temporary area with **Save movie
as...**. Your folder, base name, fps, format and bitrate are remembered between
sessions.

**Rendering window settings** are now split into Image and Render tabs, with the
log occupying the bottom pane. Umbreon quality is set per axis — Supersampling
1x–4x, AO or GI quality Low/Medium/High, Shadows Off/Hard/Soft/Very soft — and
Lighting is a single choice of Raytrace only, Ambient Occlusion or Global
Illumination. GI offers a Denoise选択 of OIDN (default), A-trous or None. The
last 50 renders are kept as history: Back / Forward in the result pane recalls
each image together with the settings that produced it. Save and Copy are back
in the result toolbar, and trackpad pinch zooms around the pointer.

Umbreon renders no longer block the app: progress is live, Stop cancels, and the
3D view keeps running. The render log now carries Umbreon's own diagnostics —
the settings actually used, any fallback and why, Embree errors, and per-phase
timings — which also makes the cost of transparency visible (one extra full
pass per transparent renderer).

Rendering fixes:

- Ambient occlusion was barely visible, and its strength depended on molecule
  size. Both are fixed; AO distance now defaults from the scene's bounding box.
- Anti-aliasing (`aa_method`, `aaJitterLevel`) only took effect when AO was
  enabled. AA is now independent, and FXAA is genuinely on by default, so
  ordinary scenes look smoother. AA and AO are chosen from preset dropdowns
  (AA: Off / Standard / High / Ultra), each applied as a single undo step.
- Camera slab clipping is honoured: cross-sections no longer draw a spurious
  outline, and spheres and cylinders are cut instead of poking through.
- Edge lines match the GL view's width (they were drawn twice as thick) and use
  round caps, so sharp corners no longer spike.
- Silhouette edge mode draws only the silhouette, instead of looking identical
  to Edges.
- With two or more transparent renderers, opaque geometry blew out to white.
- Metals under GI reflect the actual scene instead of just the background, and
  procedural-texture materials (chrome, copper, stone, wood) are no longer drawn
  as default plastic.
- Scene depth stopped occluding UI overlays on macOS.
- The image after a still render is shown fit to the pane, rather than at 100%
  or at whatever zoom was left over.

## MD trajectories

CueMol can now load and play back molecular-dynamics trajectories. Readers cover
**DCD, GROMACS XTC/TRR and AMBER NetCDF**, with no new external dependencies.

Open one with **File > Open MD Trajectory...**: pick a topology (GROMACS `.gro`)
and one or more trajectory files as an ordered list, then choose the initial
renderer as you would for any molecule. A **Trajectory tab** in the bottom pane
plays, pauses, skips, loops and seeks by dragging, takes an fps and a frame
number directly, and shows which file each frame range came from as a colour-
coded track.

Playback is fast because coordinates now live in a GPU texture that is updated
per frame instead of rebuilding geometry: CPK, Selection, Trace, Ball & Stick and
Simple renderers all take this path. A 39,593-atom morph went from roughly 3 fps
to the 60 fps vsync limit, with or without a selection displayed. A 113,961-atom
system with 1,001 frames (1.37 GB) plays back in full.

Lazy per-frame seeking and PSF topologies are not supported yet; topology files
are `.gro` only.

## Isosurfaces and colouring

Isosurface display is much faster: marching cubes is parallelised and colours
update on the GPU. On an 851k-vertex map with 8 threads, changing MOLFANC colours
went from about 1,100 ms to about 43 ms, and the initial build from about
1,130 ms to about 187 ms. Panning no longer triggers a full rebuild when the
centre has not moved, and a two-finger trackpad pan now re-centres `autoupdate`
map renderers (about 200 ms after you stop).

Isosurf gained **nearest-atom colouring** (colormode "molecule"), matching
molsurf. Isosurf colouring is configured in the Coloring panel rather than the
Inspector, with Paint / CPK / Bfac / Rainbow / Solid schemes and a reference
molecule.

The **multi-gradient editor** is no longer a modal dialog of numbers. It is an
Illustrator-style stop bar embedded in the Coloring and DensityMap panels: drag
stops directly, with a live preview while dragging, one undo step on release and
Esc to cancel. A histogram of map values sits behind it (log-scaled, so maps
where 80% of bins are empty stay readable), and the range zooms and pans with
`< - + >` / Fit, trackpad pinch, drag or horizontal wheel. Contour, isosurf and
`gpu_*` renderers are now reachable from the Coloring panel at all — previously
they were not.

Colouring is consolidated into the Coloring panel. **Paint coloring** is a
submenu with the UXP presets (Default, Woody, Red, Orange, Yellow, Green, Cyan,
Blue, Purple, plus your own styles), CPK comes in three variants (normal, dark
gray, light gray) that match the renderer context menu, and Paint > Default is
no longer empty. The now-redundant "Coloring mode" row in the molsurf Inspector
and the inline gradient editor in the Density map panel are gone; Density map
keeps Solid color, since it is the only route for contour and `gpu_*`.

## Opening and saving files

**Files can be dropped onto the window** from Finder or Explorer, going through
the same path as File > Open — renderer option dialog, scene and tab creation,
recent-files entry. An overlay marks the window while you drag, multiple files
are opened one at a time, and a drag of files nothing can read is refused before
the drop, so the OS shows a no-drop cursor rather than letting it fail
afterwards. Files no reader accepts are reported instead of being silently
ignored.

The same files can also be opened from **the shell and the command line**:
`cuemol3 foo.pdb`, macOS "Open With", a drop on the Dock tile, the Dock's recent
documents, and a second launch (which raises the running window instead of
starting another copy). On macOS, CueMol3 registers as an alternate handler, so
double-clicking a file still opens CueMol2.

Other file changes:

- Opening a `.qsc` into a freshly created, empty scene reuses that tab instead
  of adding another one, matching CueMol2.
- A scene tab is named after the file it was opened from, not `Untitled N`.
- The scene save dialog defaults to **QDF1 with xz compression**, so accepting
  it produces a compressed scene. The old QDF0 default has no compression, so
  the compression setting had no effect; QDF0 (readable by CueMol 2.2) is still
  available explicitly.
- Object **Save File As...** remembers the format you last used and preselects
  it, reports a failure instead of silently claiming success, and lists only
  objects that actually have a writer.
- **Export scene** is split by file type: PNG, Umbreon ray-traced image,
  POV-Ray SDL, STL and Metasequoia (MQO). Formats missing from your build are
  hidden rather than failing silently when chosen.
- MolSurf scenes saved with multi-gradient colouring lost their scalar-object
  reference and failed to draw on reload. Fixed, including already-broken files.

## Selections, renderers and the workspace

The **selection widget** is now four tabs — Named, History, Term, Mod. A stock
selection like `protein` applies in one click from Named, where it used to take
four steps. Mod collects Invert / Byres / Sidech / Mainch / Around / Expand, and
Term keeps keyword + value composition with Set / Add / Sub / Intsec. Hit counts
are shown per action, abbreviated as `12k` / `1.2M` past 9999.

The Selection panel was redesigned around the molecule's live selection: edits
apply immediately, and the panel's own undo stack is gone, so undo/redo is the
scene's single history rather than two competing ones.

**Renderer groups** behave as they do in CueMol2: group Show/Hide reaches the 3D
view in one undo step, renaming a group no longer makes its members vanish from
the tree, collapse state is saved in the scene, and Copy/Paste deep-copies the
group. New Renderer, File Open and Get PDB can create a whole **preset group**
(group plus child renderers) in one go. The visibility icon has three states,
greying out rows suppressed by a hidden parent.

Molecular surfaces gained **"Regenerate surface..."** in the object context
menu, for rebuilding a surface at a different point density (undoable). The
source molecule, selection and probe radius are shown read-only; only density is
editable, which is all the core API exposes.

## Interface

All menu surfaces — the Windows/Linux menu bar, the 3D view and scene tree
context menus, and text-field clipboard menus — are drawn by one component now,
in a consistent style, fixing two Windows-only defects (Open Recent expanding
inline into its parent row, and checkmarked items throwing their labels to the
end of the row). macOS keeps its native menus.

A **Window menu** switches between the main and Rendering windows. Rendering >
`POV-Ray rendering...` is now **`Image rendering...`**, joined by **`Movie
rendering...`**; both open the Rendering window in the matching mode.
`Preferences...` (Cmd+,) on macOS and Edit > `Options` (Cmd+K) elsewhere now
work, opening the Settings tab.

The Settings panel went from mostly mock to only what actually applies: default
atom-label font (family, size, colour, bold, italic) and mouse XY sensitivity and
pick precision. The font picker lists installed system fonts, renders each name
in its own face, and previews your choice live. User-defined styles are now saved
to `user_styles.xml` on exit — previously they were only ever read.

The Animation panel's timeline header regained the **Start cam** selector, and
its Start time / Duration fields accept far more than typed digits: ▲▼ steps by
one second with auto-repeat, dragging the field scrubs (0.1 s snap, Shift for
1 ms, Ctrl/Cmd for 1 s), ↑↓ adjusts the segment at the caret, and entries like
`1:30.500`, `250ms`, `1.5s` or `+2s` all parse.

CueMol3 has a proper **app icon**, at every size macOS and Windows ask for, and
it appears on development runs too. The stale CueMol2 icon in the Windows and
Linux title bar is gone.

Interface fixes:

- Numeric text boxes could not be emptied while editing — deleting a digit
  snapped the old value back, and partial input like `-` or `1.` was rejected.
  Fixed everywhere via the shared field: molecular surface density and probe
  radius, renderer properties, Settings, the colour picker's RGB/HSB, crystal
  cell parameters, CCP4 truncation and MTZ resolution limits. Surface point
  density is now a 1–5 preset combo box, and scene `Jitter SS` a 0–5 dropdown.
- Choosing a selection from the Paint coloring popovers displayed the new value
  but never recoloured the molecule.
- The Inspector pane held its width showing "No node selected."; it now
  collapses.
- Animation elements teleported when switching between relative and absolute
  time (in the worst case to a negative absolute time), negative relative times
  were accepted, elements snapped back for a frame on drop, and deleting one
  cleared the selection so you could not delete several in a row.
- Switch and checkbox focus rings overflowed their row onto neighbouring labels,
  labels broke mid-word, and numeric boxes were wider than they needed to be.
- The Component Catalog view is a design-review tool and no longer appears in
  release builds.

## Packaging and platform

- **Windows** ships an ordinary wizard installer — welcome, destination,
  install, finish — that installs for all users under Program Files with
  desktop and Start-menu shortcuts. It used to install silently per-user with no
  choice of location.
- POV-Ray, ffmpeg, apbs/pdb2pqr and blendpng are **bundled** on macOS and
  Windows, so POV-Ray rendering works without a separate installation.
- macOS bundles are ad-hoc signed for both apps. This was intended before but
  was silently skipped, leaving bundles Gatekeeper treated as damaged. Ad-hoc
  signing is not Gatekeeper acceptance: these builds are still unsigned as far
  as distribution goes, and `tritium/packaging/README.md` documents the macOS
  quarantine and Windows SmartScreen steps.
- Scenes can be rendered to PNG **headlessly**, with no GUI or GL context, via
  `cuetty --input scene.qsc --render out.png --width W --height H [--camera NAME]`
  or `python -m cuemol.umbreon_render`.
- **APBS electrostatic potential** calculation is available in CueMol3 under
  Tools > APBS elepot calculation..., producing an `ElePotMap` usable with the
  elepot surface colouring. Executable paths are configurable, and default to
  the bundled binaries.
- Packaged builds no longer forward info-level logs to a stdout nobody reads;
  warnings and errors still go through.

## Core fixes

- Quitting with a scene that used Paint colouring could crash during shutdown.
- Compiler-warning cleanup across clang, gcc and MSVC turned up real bugs: a
  malformed 64-bit ID format string, a possible null dereference when loading a
  scene file containing an invalid type name, and unchecked syscall results.
- Animation playback and rendering left animated properties written into the
  scene, corrupting undo/redo. State is now restored when playback stops or ends
  (but not on pause). CueMol2 takes the same path.
- A start camera chosen in the Animation panel was ignored when rendering, and
  rendering once overwrote the setting with `__current` permanently.
- ffmpeg failures went unnoticed, so a failed encode opened the previous movie;
  stale frames from an earlier render were not cleared; and ffmpeg's absence was
  only detected after every frame had been drawn.
- MOLFANC drawing evaluated stateful colouring schemes such as rainbow without
  initialising them, and colour lookups were offset for maps with a non-identity
  transform.
- Timer durations are pinned to nanoseconds, fixing a unit mismatch and a
  potential crash when a listener removed itself while timers were firing.
- The gtest discovery flake that randomly failed CI, and Windows CI failing
  before it started because Chocolatey refused to serve flex/bison, are both
  resolved. C++ unit tests now run on macOS as well, covering Linux, macOS
  arm64/x64 and Windows.
