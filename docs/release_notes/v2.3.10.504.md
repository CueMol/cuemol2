CueMol 2.3.10 (build 504)

This release is again mostly about **CueMol3**, the new desktop app. The
UXP -> CueMol3 porting ledger reaches **140 / 140** here: every feature area
tracked from the legacy CueMol2 GUI is now either ported or explicitly dropped.
With parity reached, the work in this release moves past it — copy and paste now
goes through the real OS clipboard and can be exchanged **with CueMol2**, the
Edit shortcuts became focus-aware, the non-photorealistic renderer gained a full
hatch-layer editor, and molecular surfaces are built by a new analytic SES
backend.

CueMol2 (the UXP app) is still built and shipped here, and gains the clipboard
interop half it needs to talk to CueMol3.

Note that CueMol3 is still a work in progress. There was no 2.3.9 release, so
everything below is what changed since 2.3.8.

> **Intel/AMD users, please read:** the x86-64 builds now require a CPU with
> **AVX2** (Intel Haswell / AMD Zen or newer, i.e. roughly 2013 and later). See
> *Packaging and platform* at the end.

---

## Molecular surfaces

**A new surface algorithm.** Solvent-excluded surfaces can now be built by
[MeshMS](https://github.com/CueMol/MeshMS), an analytic SES mesher, in addition
to the BALL-derived code CueMol has always used. Every downloadable build ships
both.

- The molecular-surface dialogs (create and regenerate) have an **Algorithm**
  dropdown — *Auto* / *MeshMS* / *BALL*. Auto picks MeshMS. BALL stays available
  for comparison, and is also used automatically if MeshMS fails on a particular
  input, so a surface always gets built.
- **Regenerating at a different density is much faster.** The density-independent
  part of the calculation is cached, so changing only the density in the
  Regenerate dialog re-runs just the meshing step. Any change to the coordinates,
  the selection or the atomic radii invalidates the cache, so a stale surface
  cannot be reused.
- The mesh density was calibrated against BALL, so the same density value gives
  a comparable amount of detail from either algorithm (the vertex-count ratio is
  now about 1.06, down from 1.39).
- Each generation writes one summary line to the log — which backend ran, how
  long it took, and the resulting vertex/face counts — so the two are directly
  comparable on your own structures.

At the same density and probe radius the two algorithms do not produce an
identical mesh; MeshMS applies one target edge length to the whole surface and
computes normals after merging, so the result should generally be smoother.
The scene file format is unchanged, so **existing scenes load exactly as before**
— a saved surface only changes once you regenerate it.

## Rendering

**The NPR (ink illustration) backend became editable.** Previously the Umbreon
NPR renderer offered a style name and two multipliers, and the multipliers did
not reach the halftone styles at all — "Mark width does nothing on manga /
screentone / stipple" was a real bug, and the shading tone could not be reached
at all, so a brightly lit scene could only be hatched as sparsely as the built-in
style decided.

- **Mark width now works for every style**, dot- and stipple-based ones included.
- A new **Detail tab** (shown for the NPR backend) treats the style you pick in
  the Render tab as a **template** and lets you edit it: per hatch layer, the
  mark kind, angle, spacing, width / dot scale, tone range, fade, opacity and ink
  darkness, with the perturbation controls under *Randomness / Advanced*; and for
  shading, **Strength** and **Curve** always visible with the rest of the tone
  recipe and the ink model under *Advanced*.
- **Reset to style** reloads the template, and an **Edited** badge marks a style
  you have changed. An unedited style renders through exactly the same path as
  before, so nothing shifts until you actually change something.
- Controls that cannot affect the picture are hidden or disabled rather than left
  to mislead — fields belonging to a different mark kind, contour parameters with
  contour darkening off, the random seed with no randomness enabled, and so on.
  A layer whose spacing has hit the renderer's minimum says so.
- Mark density and Mark width stay master multipliers on the Render tab; the
  Detail tab shows the resulting **effective** values rather than folding them
  into the layer values, so the edit stays reversible.
- Supersampling, Mark density and Mark width are now slider rows.

## Copy and paste

**Copy and paste now uses the real OS clipboard**, and — this is the point —
**a copy can be exchanged between CueMol3 and CueMol2**. Copy a renderer, a
renderer group, an object, a camera, a style or a set of paint-colouring rows in
one app and paste it in the other. Pasting recompiles the copied selections and
colours against the destination scene, so pasting across renderers and across
scenes works too.

Both apps changed for this. On macOS the legacy app's clipboard data never
actually left its own process, so CueMol2 now also publishes its clipboard
payload in a text form that CueMol3 can read, and reads that form back. On
Windows and Linux the original native format still works as before.

Two consequences worth knowing: copying in CueMol3 now replaces your text
clipboard (CueMol2 already did this), and a copy no longer survives an unrelated
copy in another application — that is what using the system clipboard means.

**Edit shortcuts are focus-aware (new).** Cmd/Ctrl+C, X and V now act on
whatever you are actually working in:

- In a text field they edit text, as always. Selecting text in the log and
  copying it still works.
- In the **scene tree** they copy, cut and paste nodes. **Cut is new** — it
  deletes only after the copy has actually reached the clipboard, and a single
  Undo brings the nodes back.
- In the **Paint colouring deck** they act on the deck's rows.

**Cmd/Ctrl+Z no longer rolls back the scene while you are typing.** Undo
previously ignored focus entirely, so undoing a typo in a text field could undo
your last scene edit instead. The toolbar Undo / Redo buttons still always act on
the scene, which is what clicking them means.

**The Paint colouring deck** gained the two commands it was missing from
CueMol2: **Delete all**, and **Cut / Copy / Paste** for its rows. Cut is a single
undo step for the whole operation, a paste keeps the copied rows in order, and
Paste is disabled when there is nothing to paste.

**The scene tree** can now copy a multi-selection (previously Show / Hide /
Delete only). Selecting a group contributes its member renderers. Mixing
different kinds of item, or selecting more than one object, is refused with the
same message CueMol2 gives.

## Scene tree, panels and the workspace

- **Shift+click extends a selection** in the scene tree, over the rows as drawn
  (a collapsed subtree's hidden children are not swept in). The anchor stays put,
  so repeated Shift+clicks re-extend from the same origin and shrinking the range
  deselects what falls outside it. Shift+Cmd/Ctrl adds to the selection instead of
  replacing it.
- **The Welcome tab is gone.** Its content was really an empty-state watermark,
  so that is what it is now: the app starts with your scene tab, and the
  watermark appears whenever every tab is closed.
- **The window title shows the active scene** (`CueMol3 - <scene>:<view>`) and
  follows the active tab. Since CueMol3 draws no OS title bar, this is what you
  see in Mission Control and the Dock on macOS, and in the taskbar / Alt-Tab on
  Windows and Linux.
- **Edit > Clear undo data** works (it was a placeholder), and the Undo / Redo
  state updates with it.
- **Reset all to default** now asks for confirmation first, is available in both
  modes of the animation element inspector, and skips properties that no longer
  exist instead of rolling the whole reset back. It also has its own icon, so it
  is no longer mistaken for Undo.
- **The Inspector's Generic tab** was rebuilt on the shared form controls, which
  fixes its inconsistent control sizing, and gained editors for the property
  types it could not edit before: **colour** (with the scene's named and
  molecule-based picker modes), **vector** (one cell per component, x/y/z/w) and
  **time**. Numeric edits now commit on blur or Enter rather than per keystroke,
  so retyping a number is one undo step instead of one per digit.
- Form polish: checkboxes no longer sit above their labels, and surface **Point
  density** is a slider with a spinner (range 1–10) instead of a preset list.
- The toolbar's non-functional **Save** button was removed. CueMol2 has no
  object-overwrite command for it to grow into; Save As and Save Scene are
  unaffected.

## Molecular tools

- **Create SYMM mol** works from the 3D view: right-click a symmetry-image atom
  on a `*symm` renderer and the symmetry copy is materialised as a new molecule,
  in a single undo step. The dialog lets you name the object.
- **Mol morphing animation** has a working dialog: pick the target, convert it to
  a morphing molecule explicitly, then add frames from PDB files (several at
  once, `.gz` accepted) or from molecules already in the scene, and delete them.
  Each edit is its own undo step. Playback is the existing Animation panel.
  Unlike CueMol2, the conversion is an explicit button rather than something that
  happens silently when you open the tool.

## Packaging and platform

- **Windows: CueMol3 now appears in Explorer's "Open with" menu** for the file
  types it handles — it was not registered at all before. It registers as a
  candidate only, so it does not take over `.pdb` from Visual Studio or `.qsc`
  from CueMol2.
- **Windows: opening a file from the shell works.** Drive-letter paths
  (`C:\...`) were being mistaken for a URL scheme and silently dropped, so
  double-clicking a file, or passing one on the command line, never reached the
  running app.
- **Linux: file associations are registered** by the deb package for the same 16
  extensions as the other platforms, so CueMol3 shows up in the file manager's
  "Open With". As on the other platforms this is a candidacy, not a takeover of
  your existing defaults. For the AppImage this depends on your desktop
  integration tool.
- **The CueMol3 downloads are named properly.** They now say which OS they are
  for in words, use one spelling per machine, carry the full four-part build
  number, and mark the two files that are installers:

  ```
  CueMol3-2.3.10.504-macOS-arm64-Installer.dmg
  CueMol3-2.3.10.504-Windows-x64-Setup.exe
  CueMol3-2.3.10.504-Linux-x64.AppImage
  CueMol3-2.3.10.504-Linux-x64.deb
  ```

- **The installer has its own icon**, distinct from the app's, on the macOS DMG
  volume and on the Windows installer and uninstaller.
- **The 2.3.8 release shipped with no files attached.** A step added for the
  release notes was deleting the freshly built artifacts before they could be
  uploaded, and the upload only warned about it. That is fixed, and the release
  job now fails outright if there is nothing to publish.
- **x86-64 builds now require AVX2.** The new surface backend is compiled for
  x86-64-v3 (Intel Haswell / AMD Zen and newer, roughly 2013 onward) in the
  release artifacts. On an older Intel or AMD CPU the app will crash when it
  generates a surface. Apple Silicon and ARM builds are unaffected.
