CueMol 2.3.11 (build 507)

The headline here is **cryo-EM density maps**, and it is what moves this release
to 2.3.11. CueMol's map code was written for crystallography and did the wrong
thing with an EM map at almost every step — it wrapped density around the box
edge, could only show a cube around a centre point, and ran out of memory on
anything large. This release adds a proper EM mode: whole-map display, level of
detail that refines as you zoom, and storage that no longer falls over on a
1300³ map.

The rest is CueMol3 refinement: opening files by content now works on current
PDB mmCIF files, the scene tree and the Paint colouring deck act on a whole
multi-selection, and a handful of interaction annoyances are gone.

CueMol2 (the UXP app) is still built and shipped here, and is unchanged in this
release apart from the shared core.

Note that CueMol3 is still a work in progress.

> **Intel/AMD users:** the x86-64 builds continue to require a CPU with **AVX2**
> (Intel Haswell / AMD Zen or newer, roughly 2013 and later), as they have since
> 2.3.10.504.

## Cryo-EM density maps

**Maps are now recognised as crystallographic or EM, and displayed accordingly.**
The kind is detected from the MRC header alone — the space-group field, a
non-zero ORIGIN, and the labels written by EMDataBank, RELION, cryoSPARC, EMAN,
IMOD and MotionCor — never from the density values, which misfire on
solvent-flattened crystal maps. You can override it per map with **Map type**
(*Auto* / *Crystallographic* / *Cryo-EM*).

What changes for an EM map:

- **No more wrap-around.** The periodic boundary that is right for a crystal map
  made an EM map fold density in from the opposite side as soon as the displayed
  region crossed the box edge. EM maps no longer use it.
- **The whole map is displayed**, not a cube around a centre point. The display
  region is a separate setting (**Region**: *Auto* / *Box* / *Full*), so you can
  still ask for the box behaviour on an EM map, or the full map on a crystal one.
- **Level of detail.** Showing an entire map at full resolution produces an
  unusable number of polygons, so the whole map is drawn at a coarser sampling
  stride chosen to fit a cell budget you can set (**Level of detail** and **LoD
  budget**). With **Refine on zoom** enabled, zooming in re-marches the visible
  part at a finer stride — you get an overview that stays responsive and detail
  where you are actually looking. This works for the isosurface, contour and
  GPU mesh renderers.
- **MRC ORIGIN is read.** It was ignored before, so a map with a non-zero origin
  did not line up with a model fitted into it.
- **The initial contour level is chosen for you** on load (the top 1% of
  density), and the view fits to the map.

**Large maps load.** Map samples are now stored in chunks rather than one huge
allocation, and the CCP4/MRC reader decodes one section at a time — its peak
memory dropped from about 5 bytes per voxel to about 1. Together these are what
make a 1300³ map possible at all; previously it hit a hard ~2 GiB single-
allocation limit and died. The reader also gained modes 1, 6 and 12.

**Before you open a very large map**, the CCP4 file-open dialog probes the header
and tells you how big it is, warning above 256 Mvoxel and suggesting a
**Subsample** factor, which you can also set yourself.

**Crystallographic maps are unaffected.** Detection defaults to crystallographic,
the other map formats (Brix, XPLOR, MTZ, mmCIF structure factors, maps embedded
in scenes) carry no EM evidence, and the periodic boundary, centre-and-extent box
and buffer limit all behave as before.

### Known incompatibilities

- An **old scene** referencing an external CCP4/MRC map that is detected as EM
  will switch from the box display to the whole-map display. Set **Map type** to
  *Crystallographic* or **Region** to *Box* to get the old view back.
- **`binning > 1` isosurfaces** look slightly different at the edge of the stored
  block: a false face used to be cut there. Vertex positions are unchanged.
- **The centre of a crystal map with a non-zero start index** moves to the
  correct position; it was off by half the map before.
- **Byte-valued (mode 0) CCP4 maps** now go through the same quantization as
  every other mode, so values read out of them differ slightly from before —
  the old raw-byte values were inconsistent with the map's own scale.
- **Scene files containing a map above 2^31 voxels** use a new chunked layout
  and cannot be opened by older CueMol. Smaller maps are written exactly as
  before and stay compatible.
- **The `gpu_mapmesh` renderer is no longer offered when creating a renderer.**
  Its shader never actually compiled in CueMol3, so it drew nothing; that is
  fixed, but it has a fixed line width and is slower than the CPU contour, so
  the contour renderer is the better choice. Existing scenes that use it load
  and draw normally.

## Opening files

**Current PDB mmCIF files are recognised again when opening by content.** The
sniffer waits for the coordinate section, which in a modern RCSB mmCIF sits
hundreds of kilobytes into the file (271 KB for 5IRE, 462 KB for 7A6A) because
the header has grown. Only the first 64 KB was ever examined, so opening a local
`.cif` by content found no reader at all. Files downloaded through *Get PDB* were
unaffected, since those go by extension.

Rather than just reading further for every file, the sniffer now starts small and
**reads further only for the readers that were actually cut off** — so a format
that identifies itself in its first bytes still costs a few bytes, while a file
whose marker is deep in still resolves. A file that no reader can identify is
given up on after a bounded amount of reading, so dropping an unrecognised file
on the app cannot stall it.

## Scene tree and Paint colouring

**The scene tree's multi-selection now reaches its actions.**

- **Shift+click extends the selection.** This was implemented but never actually
  connected, so it did nothing in the released app.
- **The Delete button deletes the whole selection**, in one undo step. It
  previously deleted only the row you selected last, even with several rows
  highlighted — a bulk delete was reachable only from the right-click menu.
- **Delete / Backspace** removes the selection, so it no longer needs the menu.
- Deleting a **renderer group together with one of its own members** no longer
  double-frees that member.

**The Paint colouring deck supports multi-selection.** Cmd/Ctrl+click toggles a
row, Shift+click selects a range, and **Delete, Cut and Copy act on every
selected row**. Move up / down stay single-row on purpose: applying them to a
scattered selection would pull the rows together into one block.

**The deck's toolbar fits on one line again.** It keeps Add, Delete and Move up /
down; **Delete all, Cut, Copy and Paste moved to the row's right-click menu**,
which is where CueMol2 keeps them. Cmd/Ctrl+X, C and V work on the deck exactly
as before.

**The Selection / Colour split can be dragged**, as it could in CueMol2, and the
width is remembered.

## Rendering and interaction

- **Ambient occlusion presets are usable while you tumble.** *Medium* and *High*
  now compute AO at half resolution while the camera is moving and re-render at
  full resolution once the view settles. Exported images are always full
  resolution.
- **Cut, Copy and Paste work inside dialogs on macOS.** Opening any dialog
  disabled the entire application menu — which on macOS is what owns
  Cmd+X/C/V/A/Z — so text fields in every dialog, the *Get PDB* box included,
  could not paste at all. Only the right-click menu worked.
- **The wait cursor no longer flickers.** It appeared for operations that finish
  in a blink, which read as a glitch rather than as feedback; it now waits until
  an operation is actually worth interrupting for.
- **More numeric settings are sliders**: the ray tracer's AO samples, distance,
  intensity and direct-light amount; the surface renderers' Detail; and the
  probe radius in the molecular-surface dialog.
