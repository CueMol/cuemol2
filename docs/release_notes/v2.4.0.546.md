CueMol 2.4.0 (build 546)

This release makes **US-align the default superposition** in CueMol3, which
also makes it possible to superpose **RNA and DNA**. CueMol3 also gains an
**Actions** view: a **History** pane that shows every undo step as the
operations it ran, and an **Actions** pane of presets and your own macros, saved
as `.qax` files and replayed on other objects.

The console learns zsh habits: **wildcards and lists of targets**
(`hide *`, `load *.pdb`), a **Tab completion menu**, **Markdown help** and
property tables, and `quit`. On macOS (Apple silicon), CueMol3 can now **update
itself**. The app has a new icon.

CueMol2 (the UXP app) picks up the shared core changes: name label and style
set edits made from scripts are now undo steps.

---

## Superposition: US-align (CueMol3, default)

- The Superpose dialog has a **Method** choice (US-align / SSM / LSQ), with
  US-align selected by default, and a **Pivot atom**: `auto` uses CA for amino
  acids and C3' for nucleotides (modified bases included), or name an atom such
  as `P`. The pivot is kept in the dialog history.
- US-align works on proteins and on **RNA / DNA**, which SSM cannot superpose.
- The console's `superpose` takes a `pivot` argument. PyMOL `align` / `super`
  use US-align and print the RMSD, the number of aligned residues and the
  TM-score.
- SSM and LSQ are still available and behave as before.

## Actions view (CueMol3)

A new **Actions** view in the activity bar.

### History pane

- One row per undo step of the active scene, with the operations it ran as
  child rows, an Initial state row, and marks for undone steps and the current
  one.
- **Go to step** moves the undo stack to a row. **Save as qax** and **Copy as
  commands** (also Edit > Copy) export the selected rows.
- Double-click a step (or click one of its operations) to see it read-only in
  the Inspector.
- Undo / Redo texts, including the toolbar's Undo / Redo dropdowns, are now
  written from the operations, e.g. which renderer was created or which
  property was set.
- Almost every GUI and PyMOL-dialect edit is recorded as an operation that can
  be saved and replayed: properties, loading and fetching, renderers and
  styles, coloring and paint, selections, molecule editing, superposition,
  labels and measurement, symmetry, morphing, animation, cameras, style sets,
  APBS, copy / paste and more. MD trajectory edits are not recorded yet.

### Actions pane

- Lists **12 presets** shipped with the app (display, figure finishing,
  analysis, motion) and **your own actions** (qax files in the app's user data
  `actions` folder).
- **Run** applies an action to the object(s) selected in the scene tree (a
  selected renderer means its object; with no selection, the only object).
  Running it on several objects is one undo step; an object it fails on is
  skipped and listed at the end.
- Context menu: Run, Copy to User Actions, Rename, Move to Trash, Open in
  Editor, Reveal in Finder.
- **Save to Actions** in the History pane saves the selected steps, optionally
  as a **macro** that can run on another object. When the steps cannot be a
  macro (they touch two objects, or a renderer they do not create), the dialog
  says why.

### qax files and the console

- qax is an XML file of recorded actions. `run x.qax` (or `@x.qax`) in the
  console replays each action as its own undo step; `tritium_cli x.qax` does
  the same.
- `list_actions` and `export_actions file[, first[, last]]` list and save the
  recorded steps; `open_log` now writes qax.
- The PyMOL dialect does not run qax files.

## Console and `tritium_cli` (CueMol3)

- **Several targets at once.** Object, renderer, property-path and load-path
  arguments take a list of words and `*` / `?` wildcards, as in zsh:
  `hide 1crn 2abc/cartoon1`, `set */simple1.width, 0.7`,
  `load *.pdb ~/pdb/1c*.pdb`, `get_prop *.visible`. Quotes and `\` keep text
  literal (`"my mol"`, `my\ mol`, `\*`).
  - The command runs once per target; a target it fails on gives a warning and
    the rest still run. A pattern that matches nothing warns
    `no matches found: <pattern>`.
  - The whole line is still one undo step.
- **Tab completion menu** in the panel and in `tritium_cli`: candidates in
  columns, and a second Tab opens a menu (Tab / Shift-Tab / arrows, Enter
  accepts, Esc restores). Tab on a wildcard expands it to every match. File
  names complete as in zsh (dot files only when you type the dot,
  case-insensitive retry, `cd` lists directories only).
- **Markdown help**: `help` lists subjects, `help <subject>` the commands of
  one subject, `help <command>` the usage and an argument table; `help syntax`
  explains how commands are written. In `tritium_cli` it is wrapped to the
  terminal width (raw Markdown when piped).
- **Property tables**: `props` (`list_node_props`) and `get` (`get_prop`) print
  a table; over several targets they merge into one.
- **`quit`** quits the app from the console (with the usual save prompts;
  `quit force=true` / `quit -f` skips them). In `tritium_cli`, `quit` quits the
  app and the CLI, `exit` only leaves the CLI.
- The **Console tab is now the first tab** of the bottom panel and is shown
  until you pick another one.

## Self-update (CueMol3, macOS Apple silicon)

- CueMol3 checks for a new release at startup (you can turn this off in
  **Settings > General > Updates**), and **Check for Updates** is in the app
  menu.
- **Update** downloads the new version, checks it, and replaces the app after
  it quits, then restarts. If the new version does not start, the previous one
  is restored.
- Progress and results are shown in a new notification center (the bell in the
  status bar).
- Not yet available on Windows or Linux.
- 2.3.21 and earlier have no updater: install this release by hand once, and
  later releases can be installed from inside the app.

## Other changes in CueMol3

- New app icon.
- macOS no longer asks for the Keychain password at launch to read the local
  API (MCP / `tritium_cli`) token.
- Settings: path and text rows use the full width; the MCP port is a text field
  applied on Enter or when you leave it, with range validation.
- Dragging a scene tree row upward drops it at the right place.
- Electron 42.10.0.

## Known incompatibilities and limitations

- **Names with spaces need quotes** in the native console: an object, renderer
  or load path with spaces is written `"my mol"` or `my\ mol` (it used to be
  accepted bare).
- **Operation arguments renamed** (console, MCP, AI agent, qax): paint and
  coloring operations (`add_paint`, `set_paint`, `clear_paint`,
  `set_default_color`, `set_renderer_coloring`, ...) take `nodeId` + `nodeType`
  instead of `rendId`, and arguments that named an object as `molId` are now
  `objId` (`add_morph_frame`: `fromMolId` -> `fromObjId`).
- The style set created for a scene that has no writable one is now named
  `default` (was `style_1`).
- Macros run only with no parameter or a single object parameter.
- Self-update is macOS arm64 only.
