CueMol 2.3.13 (build 523)

This release is mostly about rendering and density maps. Rendering settings now
live in the scene file, umbreon's GI lighting is rebalanced with a five-step
ladder, edge groups decide where contact contours are drawn, and `cuetty` and the
Python module render a scene the way the Rendering window does. Cryo-EM maps get a
data-independent contour level with their own defaults, opening a map no longer
throws the view to the origin, and direct surfaces gain multi-gradient colouring.
The animation timeline has a segmented time editor with live preview, the dark
theme is readable again, and the packaged app is about 150 MB smaller.

CueMol2 (the UXP app) is unchanged apart from the shared core. CueMol3 is still a
work in progress.

---

## Rendering (umbreon / POV-Ray)

**Render settings are saved with the scene.** The Rendering window's settings
(POV-Ray / umbreon / umbreon NPR) used to live only in memory, shared by every
scene and lost on close. They are now stored in the `.qsc` and restored per scene;
editing them is an undoable scene edit (Cmd+Z / Shift+Cmd+Z work in the Rendering
window too), and "Use settings" on a history entry is one undo step. Only values
you changed from the defaults are written, so a scene you never touched carries
nothing. A scene saved by a newer build with settings this build does not know
keeps them verbatim.

**GI lighting is rebalanced.** With GI on, umbreon took the POV radiosity light
split literally, which gave open surfaces about three times the fill of the
raytraced picture while dimming the direct lights -- a brighter, flatter image in
which white tubes lost their shading. The Rendering window now has a **GI
lighting** ladder of five steps: step 0 reproduces the raytraced picture, and each
step moves headlight energy into the key light and the GI gather at a constant
mean brightness. Step 4 is the default, with a new gradient sky (a ground tint
along the camera's up axis that changes how the ambient shades by orientation, not
how bright it is). A **Lights** group (light intensity / flash fraction) applies to
every lighting method, and picking a direct method restores its own defaults. GI
intensity / GI environment leave the UI (the ladder covers them; the properties
stay for scripts), and GI quality is a plain sample-count dropdown (8 / 32 / 64 /
256) since the denoiser renders the old steps near-identical.

**Edge groups decide where contact contours go.** umbreon's edge pass treats an
*edge group*, not a renderer, as one section: a depth-continuous contact contour
is drawn between groups and never inside one, and a group carries one line style.
Renderers with the same non-empty **`egroup`** name form a group; with the default
empty name, renderers that draw the same edge lines (type, width, colour) are one
group wherever they sit in the scene. That puts the contour where it carries
information -- a ball-and-stick plunging into a ribbon -- and not between two
renderers of one cartoon. **`contactEdges` now defaults to on**; it only decides
whether cross-group contours are drawn at all. The style of a cross-group contour
comes from the side whose line is wider, then darker.

**Silhouette mode and the depth fog.** umbreon now clips at the same far plane as
the interactive view (it had no far plane at all), so nothing beyond it is drawn
and the zone past the fog end is fully fogged. A new **Outline far depth** (0..1
into the fog range, default 0.2) lets a contour in silhouette mode show over a
same-group surface that has been fogged away instead of being suppressed as
self-occlusion. **Crease angle** is a real fold-angle threshold for umbreon (Off /
15 / 30 / 45 / 60 / 90 / 120 degrees; a larger angle inks fewer, sharper folds)
where before it was only an on/off gate, and *Edge rise*, which only POV-Ray uses,
is hidden on the umbreon pages.

**Ink blobs inside atoms are gone.** Stick bonds were handed to umbreon as
round-capped capsules whose end caps coincided exactly with the atom spheres, and
at extreme zoom the edge pass read the resulting depth jitter as a field of tiny
steps and drew blobs of ink inside the atom. Bonds are now closed cylinders, as the
POV-Ray exporter has always written them.

**`cuetty --render` and the Python module render like the app.** They apply the
scene's stored render settings through the same mapping the Rendering window uses;
a scene without any renders with the defaults (GI lighting, 1200x1200 px) and the
saved camera's projection. `--width` / `--height` (`-W` / `-H`) are now overrides
of the stored size, `cuetty` exits with status 1 when a render fails, and the
Python module gains `apply_scene_settings()`. Note that a scene without stored
settings now renders with GI, which is slower than the previous raytrace default.

## Density maps and surfaces

**Cryo-EM maps have their own contour level and defaults.** The contour level is
now a data-independent number in the map's native unit: sigma multiples on a
crystallographic map, the top percent of grid points on a cryo-EM map (the
ChimeraX initial-contour rule). It is saved, reset and restored like any other
property, so "Reset to default" on an EM renderer restores the EM level (top 1
percent, absolute-unit display) instead of the crystallographic 1.1 sigma. A
contour / isosurface renderer takes the style of its map's kind when it is
created, and changing a map's **Map type** swaps the styles of its renderers in the
same undo step, leaving styles you picked yourself alone. The Density map pane's
Level field works in the native unit or in absolute units and shows the same level
in the other unit as a caption.

**Opening a density map behaves.** Opening a 2Fo-Fc map over a model used to throw
the camera to the origin and leave the map drawing an empty box there. The file
open dialog now has a **View after loading** choice for maps: *Set map center*
(keep the view, bring the map to it -- the CueMol2 default), *Move view center*
(fit the view to the whole map), or *Auto* (default: fit for a cryo-EM map, map
center for a crystallographic one). BRIX / mmCIF / QDF / X-PLOR maps are no longer
offered an atom selection as if they were molecules.

**You can see what kind of map you have.** The DensityMap object has its own
Inspector page with an editable *Map type* and the resolved kind read-only; map
renderers show the kind too. The isosurface page exposes **Cap mode** (Auto / On /
Off), which was added to the core in 2.3.12 but never reached the GUI, and the
default isosurface colour is a neutral light gray instead of the saturated
contour blue, so the shape reads. The APBS charge-method widget is a normal
dropdown.

**Multi-gradient colouring for direct surfaces.** `dsurface` and `dsurf2` gain the
multi-gradient colouring mode that `molsurf` already had (electrostatic potential
through APBS, live stop editing, saved and reloaded with the scene). A latent bug
turned up on the way: the EDTSurf radius table had six uninitialised slots that the
surface builder allocated from.

## CueMol3: working in the app

**Animation timeline.** The time editor is a segmented `H:MM:SS.mmm` field in the
style of Blender / After Effects: click a segment, drag it to scrub by its unit
(Shift = precision, Ctrl / Cmd = x10), step it with Up / Down, type digits to
overwrite and carry, or open the expression editor with Enter / double-click.
Start / Duration in the Inspector preview live as you drag and commit one undo
step, and the transport clock is editable -- type a timecode and Enter to seek.
Time-reference chains are guarded end to end: a write that would create a cycle,
a duplicate name or a dangling reference is refused with the reason, unresolved
strips are hatched and Play / seek are disabled until the chain is fixed, and a
dangling reference shows as `(missing: NAME)`. Deleting an element no longer
clears the redo stack through an empty transaction.

**Scene settings in the New Tab dialog.** The New Scene mode carries anti-aliasing,
ambient occlusion, background colour and CMYK proofing, and what you confirm
becomes the defaults every new scene starts from -- including the one made at
launch or by a file drop. Setting them does not mark the fresh scene modified.

**Picking after a superpose.** The hittest cache held atoms at their old positions
after a superpose, so clicking picked the wrong atom on tube / ribbon / cartoon
renderers and on the "transform by property" path for every renderer.

**Paint colouring lands on the renderer.** The Coloring panel wrote to the object
even with a renderer selected, and "Default" for a renderer was a style rather than
a paint colouring, so the paint silently did nothing on ribbon / cartoon / tube.
The target now follows the scene tree and the real paint colouring is offered
first ("Molecule color" is the style).

**Renaming a renderer group no longer freezes the app.** Renaming from the Generic
tab, or ticking its "default" box, left the group nameless and matched every
ungrouped renderer. `name` / `sel` are non-resettable throughout, the Generic tab
stays open across a rename, and the Name field follows an external rename.

**Selection history covers every surface that applies a selection**, as CueMol2's
did: Inspector selection rows, the New Renderer dialog, the scene tree / sequence
panel / context-menu Selection submenus, rectangle / lasso selection, the Mol
Struct pane and residue picks (a run of picks keeps only its final state). The
list holds 100 entries instead of 40.

**Smaller ones:** the dark theme's muted text had drifted to a 2.26:1 contrast
ratio -- dimmer than the disabled tone -- so enabled controls such as the
scene-tree carets looked disabled; the ladder is re-tuned and interactive glyphs
take the primary text colour. The atom-interaction label font is a picker over the
installed families. The Scene inspector shows all its sections at once instead of
one accordion at a time. Windows and Linux get new app icon artwork.

## Packaging and platform

- **The packaged app is about 150 MB smaller.** Renderer-only npm packages were
  shipped alongside the bundle that already contained them, an unused
  `libpython` was staged, and the native binaries carried their local symbol
  tables. On macOS the `.app` goes from 580 MB to 414 MB and the DMG from 226 MB
  to 197 MB.
- Electron 42.5.1.

## Known incompatibilities

- **EM map contour levels in scenes saved by 2.3.11.507 or 2.3.12.517.** On an EM
  map `siglevel` is now a top percent, not sigma. If the level of an EM renderer
  had been dragged, the saved number is read as a percent and the surface will
  look different -- adjust the level once. Untouched ones fall to the class default
  (top 1.1 percent). Crystallographic maps are unchanged.
- **Contact contours appear where they did not.** `contactEdges` now defaults to
  on, and renderers that share edge settings merge into one edge group. A scene
  whose chains all use one style loses the contours between chains; give each
  chain its own `egroup` name to bring them back.
- **umbreon renders now clip at the far plane** like the interactive view.
  Geometry beyond it, which used to be drawn fully fogged, is gone.
- **`cuetty` / Python render with GI by default** when the scene stores no render
  settings.
- **Map type / Subsample panes are not offered** for BRIX / mmCIF / QDF / X-PLOR
  maps in the file open dialog (Map type can be set from the Inspector after
  loading). Focusing a map *renderer* row in the scene tree still flies to the
  origin; focus the object row instead.
- **Renderer groups are still matched by name in the core.** The GUI guards
  against making a group nameless, but scripts and older files can still do it.
- **GI intensity / GI environment are no longer in the Rendering window**; they
  remain as properties for scripts.
