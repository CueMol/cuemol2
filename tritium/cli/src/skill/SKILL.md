# CueMol3 through tritium_cli

CueMol3 is a desktop viewer for macromolecular structures (proteins, nucleic
acids, electron density maps). `tritium_cli` sends console commands to the
running app; they act on the **active tab** (scene) the user is looking at,
exactly as if typed into the app's console panel. If CueMol3 is not running,
`tritium_cli` starts it (use `--no-launch` to fail instead).

## Check that it is there

```sh
tritium_cli status      # exit 0: running; 1: not running (does not start it)
tritium_cli --version
```

## Run commands

```sh
tritium_cli -c "fetch 1crn; create_renderer 1crn, ribbon"
tritium_cli -c "help"              # every command, as Markdown
tritium_cli -c "help create_renderer"   # one command: usage, arguments
```

- Separate commands with `;` (or newlines). One `-c` is one submission and
  **one undo step** in CueMol; if a command fails, the rest are not run.
- **Get the command list from `tritium_cli -c help`, not from memory.** It is
  generated by the app itself, so it always matches the installed version.
  Piped (not a terminal), help prints plain Markdown.
- Output goes to stdout; warnings and errors to stderr.
- Exit status: 0 success, 1 a command failed, 2 usage error, 130 interrupted.
- Relative paths are resolved against the shell's working directory; prefer
  absolute paths.

## Open files

```sh
tritium_cli 1crn.pdb                          # open, then exit
tritium_cli model.cif map.ccp4 -c "list_scenes"
tritium_cli scene.qsc                         # a saved scene opens in a new tab
tritium_cli script.qax                        # run a script (.qax, .pml, .cxc, .txt)
```

The reader is picked the way File > Open picks it (by extension, or by the
content), with its default options. Data files and `-c` run as one undo step
in the active tab; a `.qsc` scene opens first and the rest goes into it.

## Dialects

The default (native) dialect is generated from CueMol's operation catalogue.
Partial PyMOL and ChimeraX dialects are available too (a `.pml` / `.cxc` file
runs in its own dialect):

```sh
tritium_cli --dialect pymol -c "fetch 1ubq; hide everything; show sticks, resn LYS"
tritium_cli --dialect chimerax -c "open 1ubq; col byh; show :LYS atoms; view"
```

## Scenes (tabs)

`list_scenes` (or `scenes`), `create_scene [name]`, `switch_scene <scene>`,
`close_scene [scene]`. A scene with unsaved changes is not closed unless
`discardChanges` is true -- ask the user before discarding anything.

## Selections

Commands that take a selection use CueMol's selection language, e.g.
`chain A`, `resid 10:20`, `resn ALA,GLY`, `name CA`, `elem C,N,O`,
`chain A and resid 45`, `byres (resn HEM around 5.0)`, `protein`, `nucleic`.
Operators: `and`, `or`, `not`, parentheses; `around` / `expand` take a
distance in angstroms.

## Good practice

- Look before you change: list what is in the scene and use the names it
  reports rather than guessing.
- Write files (images, saved objects, scenes) only when the user asks.
- One client edits at a time. If another `tritium_cli` or MCP client is
  running something, a command fails with "CueMol is busy"; wait and retry.
- `tritium_cli -c quit` quits CueMol itself (it asks the user to save
  changes). Do not quit the user's app unless asked.

## MCP instead

For an MCP client, `tritium_cli mcp` serves the same operations as MCP tools
over stdin/stdout, e.g. `claude mcp add cuemol -- tritium_cli mcp`.
